## Update rules

All start at 1500, scale 400, decided matches only (a winner, or draw/tie scoring 0.5), `expected = 1/(1+10^((Eb-Ea)/400))`, `base = score - expected`, `Ea += kA*mult*base`, `Eb -= kB*mult*base`.

- prod: K = 24, mult = 1.
- kByGames1 (a): `K = 48 * max(0.5, 1/sqrt(1 + games/10))` per side. kByGames2: `K = 64 * max(0.375, 1/sqrt(1 + games/20))`.
- mov90 / mov120 (b): K0 = 90 / 120, `mult = ln(1 + norm) * 2.2 / (winnerLead*0.001 + 2.2)`, winnerLead = winner's rating minus loser's (0 for a draw). norm: batting-first win = (first runs - second runs)/first runs; chase win = 0.5*(10 - wickets lost)/10 + 0.5*ballsLeft/ballsBudget; 0.3 for Tests, draws, ties and matches without innings data. K0 is higher than 24 because mean ln(1+norm) is about 0.26.
- idle365 / idle730 (c): before a match, each side moves toward the mean rating of its format x gender by `1 - exp(-daysIdle/tau)`, tau = 365 / 730.
- shrink10 / shrink30 (d2): eloDiff uses `1500 + (E-1500)*games/(games+m)` per side, m = 10 / 30. gamesLog (d1): extra column `log1p(gamesA) - log1p(gamesB)`.
- (e) fitted Elo-to-logit scale: skipped. eloDiff is a linear column in a logistic model, so its fitted coefficient is that scale.
- combined (f): the best passing-direction variant of each family (delta < 0), merged: see the `combinedFrom` line per head. Pre-match and first innings combine kByGames2 + mov120 (K0 90 with kg parameters g0 20, kMin 0.375, mov on); chase also adds idle365 and shrink30.

## Serving cost

Elo is shipped in the model tables (`wpx-` shards, `exportTeams()` rating per team), so a winner is a trainer-side change: `asOfState.js` `update` (margin norm from the match's innings totals, or K by games, which already has `games`) and a regenerated shipped team table. The served feature stays `(Ea - Eb)/400`, the same column in the same position, so there is no new column, no `contextmath.js` change and no vendored-copy parity change. A rating that was refit also needs the models refit against it, since the coefficient and calibration move with the rating scale (K0 120 gives a wider spread than K 24); that happens in the normal trainer run.

match-sync: no change. It reads whatever rating the table carries. Only a `gamesLog` column would touch `contextmath.js` (both copies plus `ContextMathVendorParityTest`), and it is not recommended.

Not touched: trainer and match-sync sources (another agent is editing the trainer).
