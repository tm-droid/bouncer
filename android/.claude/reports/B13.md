# B13 + B14: context build on failed reads, squads paired by position

## B13 (N4): real

`contextstore.js` `shard()` turned every `readJson` error into null. `build` then produced a context with empty team tables, and `ensure` stored it as `mc-{id}` and kept it in memory. Nothing in the rebuild triggers (`!context`, stale model or version, no eleven) covered it, so one transient 5xx left empty tables for the match's life.

Fix (`src/contextstore.js`):
- Only `code === 404` (or a null return) is a genuine empty shard; it is cached 5 min as before.
- Any other error is not cached, is logged, and is collected in `failed` for that build (also for `wps-<letter>` pools).
- `ensure` records the match in a `degraded` set. A degraded build is never written (also not by the forecast refresh), replaces nothing already held, and `degraded.has(id)` is a rebuild trigger, bounded by the existing `BUILDS_PER_RUN = 2`.
- The set is in memory, which is enough: a degraded context is never stored, so a cold container starts from nothing and builds again.

Test: "a shard that fails to read leaves a context that is not stored as final..." (fails before the fix). Pin: "a shard that does not exist is an empty shard" (404 is stored, not rebuilt).

Not changed: `patch()` (preview, summary) still writes the held context, which can be degraded. The next rebuild replaces it either way, since `buildContext` does not carry those fields.

## B14 (N5): real

`surnameLettersFor` paired `squads.team1/team2` with `teams[0]/teams[1]` by position. `parseSquads` sides carry `teamId` and `name`, and `buildContext` already pairs by id, so only the surname-pool choice was wrong: with the page in the other order, each side's players were checked against the other side's roster and the wrong `wps-` pools were fetched.

Fix (`src/context.js`): each team is matched to a squad by team id, else by normalised name, never by position. `contextstore.build` now passes `{key, id, name}`.

Test: "squads listed in the other order..." (fails before the fix, by id and by name).
