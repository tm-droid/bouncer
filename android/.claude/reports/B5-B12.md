## B5 symmetric pre-match head
New in training.js, one path: `fitSymmetricHead(train, valid, antisymmetric = PREMATCH_ANTISYMMETRIC, options)`.
Both orientations per row (antisymmetric columns negated, label flipped), `trainBinary` option `fitBias:false` (bias stays 0), `RowSink.fitStandardizer({center:false})` (means 0), non-antisymmetric columns excluded from the fit. Returns full-layout {weights (0 on dropped), bias 0, featureMeans 0, featureStds, validLogLoss, epoch}.
Test: fits on 300 skewed rows (first-named side wins ~70%, ODI skew), asserts |p(A,B)+p(B,A)-1|<1e-9 over 6 strengths x 4 formats through a copy of serving's scoreBinary with temperature 1.3, and p=0.5 at diff 0.
Non-antisymmetric pre-match features: isOdi, isHundred, isLongFormat (format indicators); in contextFeatures also venueScoring-1, hasVenue, xiCoverage. Antisymmetric: teamStrengthDiff, eloDiff, formDiff, h2hAdvantage, winRateDiff, familiarityDiff, batAvgDiff, batStrikeDiff, batRecentDiff, bowlDiff.
Serving: no change (scoreBinary with bias 0, means 0, weight 0 on dropped columns is exactly odd; temperature is a scalar). Caveat: scoreBinary must not add a bias default other than 0, and the manifest artifact must keep the full layout.
build.js (not edited) needs: in fitTier/fitHead's pre-match path call `fitSymmetricHead` with a mask for the context vector (true only for the diff columns above; dropping venueScoring/hasVenue/xiCoverage/format flags), then fitTemperature on the mirrored validation rows, and feed it rows [{features,label}] from prematchContextRows. Label orientation is arbitrary so mirroring is lossless. Cost: format-specific base rates and venue effects vanish from this head (measure in the lab).
Also stale doc: prematchFeatures' comment claims symmetry by construction; it was not (format flags + intercept).
